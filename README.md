# Bee Schematic Lab

Веб-редактор и генератор ванильных схем **Mindustry v160.2**. Программа работает в браузере: она создаёт схему на компьютере пользователя и не требует отдельного сервера или аккаунта.

Ниже — инструкция для тех, кто раньше не запускал проекты из GitHub.

## Что нужно установить

Для запуска понадобятся:

- **Git** — нужен для скачивания и обновления проекта;
- любой современный браузер: Chrome, Firefox, Edge или Chromium.

**Node.js скачивается автоматически** установщиком на Ubuntu / Debian / Linux Mint. Он устанавливает актуальную LTS-версию в домашнюю папку пользователя через nvm, поэтому вручную ставить Node.js не нужно. При ручном запуске на Windows или macOS Node.js 18+ нужно установить самостоятельно.

> Если вы используете Ubuntu, Debian или Linux Mint, воспользуйтесь автоматическим способом ниже — он сам установит все необходимые инструменты.

## Вариант 1: самый простой запуск на Ubuntu / Debian / Linux Mint

1. Откройте приложение **Терминал**.
2. Скачайте проект и перейдите в его папку:

   ```bash
   git clone https://github.com/danilka-revin/esp32-----html.git
   cd esp32-----html
   ```

3. Запустите установщик:

   ```bash
   bash scripts/install-shortcut.sh
   ```

4. Если установщик спросит пароль, введите пароль от своей учётной записи Linux. При вводе символы не отображаются — это нормально. Нажмите **Enter**.
5. На вопрос о запуске приложения нажмите **Enter** или введите `Y`.
6. После установки приложение появится в меню приложений под названием **Bee Schematic Lab**.

Установщик сам:

- проверит Git, Node.js, npm и другие необходимые команды;
- при необходимости предложит установить их;
- установит зависимости проекта;
- соберёт приложение;
- создаст ярлык с иконкой в меню приложений.

### Как запускать потом

Найдите **Bee Schematic Lab** в меню приложений и нажмите на него. При запуске ярлык проверяет обновления, пересобирает приложение и открывает его в браузере.

Если ярлык ещё не появился, можно запустить программу из папки проекта:

```bash
cd esp32-----html
bash scripts/launcher.sh
```

Чтобы остановить программу, вернитесь в окно терминала и нажмите **Ctrl+C**.

## Вариант 2: ручной запуск на любой системе

Этот способ подходит для Windows, macOS и Linux, если Git и Node.js уже установлены.

### Шаг 1. Скачать проект

Скачайте проект кнопкой **Code → Download ZIP** на GitHub и распакуйте архив. Либо выполните в терминале:

```bash
git clone https://github.com/danilka-revin/esp32-----html.git
cd esp32-----html
```

Важно: команды нужно выполнять **в папке, где лежит файл `package.json`**.

### Шаг 2. Установить зависимости

Откройте терминал в папке проекта и выполните:

```bash
npm install
```

Первый запуск может занять несколько минут. Команда создаст папку `node_modules` — удалять её не нужно.

### Шаг 3. Запустить приложение

```bash
npm run dev
```

В терминале появится адрес вроде:

```text
http://localhost:5173
```

Скопируйте этот адрес в браузер. Пока окно терминала открыто, приложение работает. Для остановки нажмите **Ctrl+C**.

> Если браузер не открылся сам, это не ошибка: просто вставьте показанный адрес в адресную строку вручную.

## Как пользоваться программой

1. Слева выберите **направление**: добыча, производство, оборона, энергия, логистика, юниты, логика или кампания.
2. Выберите **этап игры** и **планету** — Серпуло или Эрекир. Список целей зависит от планеты: например, на Эрекире нет солнечных панелей, а логика и кампания есть только на Серпуло.
3. В поле **Цель схемы** укажите нужный ресурс или задачу.
4. При необходимости настройте снабжение, размер, плотность, питание, защиту и хранилище.
5. Нажмите **Сгенерировать схему**. Откроется выбор компоновок (до трёх): у каждой видны размер, число блоков, смета и вердикт проверки потоков, лучшая по оценке помечена «Рекомендуем».
6. Проверьте результат на сетке и в панели **Проверка схемы** справа. Блоки можно выбирать, перемещать, поворачивать и удалять — проверка пересчитывается после каждой правки.
7. Нажмите **Экспорт .msch** и сохраните файл.
8. В Mindustry импортируйте сохранённый файл как обычную схему.

### Панель «Проверка схемы»

Справа в инспекторе каждая схема проверяется по механике Mindustry v160.2:

- **Ошибка** — поток не доходит до потребителя: лента упирается в пустоту или в блок, который не принимает предмет; ленты направлены друг на друга; турель без боеприпаса; фабрика, генератор или завод юнитов без нужного ингредиента или топлива; разгрузчик не касается склада; выход фабрики никуда не отведён; блок без источника энергии. Клик по строке выделяет блок на поле, проблемные блоки обведены рамкой.
- **Внимание** — схема работает, но есть риск: нехватка энергии в сети, жидкость не подведена, продукт не доходит до ядра. Отдельно панель «Механики» и карточки выбора предупреждают, что блок для выбранного этапа слишком дорог.
- **Подключить** — места, где схему нужно соединить с внешним миром: вход сырья, жидкости, внешняя энергия. На поле они отмечены кружками (жёлтый — предметы, голубой — жидкость, светло-жёлтый — энергия); общий список «Подключи снаружи» стоит под вердиктом.

Если генератор не смог что-то построить (не хватило места, нет такого блока на планете), он не молчит, а пишет это в список ошибок. После ручной правки этот список снимается: дальше схему оценивает только живая проверка.

### Импорт готовой схемы

- кнопка **Импорт** загружает файл `.msch` с компьютера;
- кнопка **Вставить** принимает строку схемы из буфера обмена;
- кнопка **Сохранить** сохраняет текущую схему в браузере;
- **Ctrl+Z** отменяет действие, **Ctrl+Shift+Z** возвращает его.

### Важное про MLOG и Эрекир

На Серпуло для режимов снабжения с MLOG (дроны, гибрид, контроль резерва от ядра) процессор уже стоит в схеме, а его код и связи с блоками записаны в `.msch` в формате самой игры: после вставки в игру настраивать его вручную не нужно. Тот же код показан в панели **MLOG / процессор**, его можно скопировать кнопкой «Скопировать MLOG». Для доставки нужен юнит (по умолчанию mono) — выпустите его заводом юнитов в зоне процессора.

На Эрекире нельзя выгружать предметы из ядра напрямую, поэтому генератор ставит усиленный контейнер, который не касается ядра, и канальные разгрузчики за ним; вход контейнера отмечен на поле — его нужно наполнять извне. В режиме дронов схема содержит Unit Cargo Loader и точку выгрузки, настроенную на предмет. Загрузчику нужны питание (генератор уже в схеме, а при выключенной энергии — отмеченный вход внешнего питания) и азот (вход отмечен на поле): без азота Manifold не создаётся.

## Проверка проекта

```bash
npm test                          # все тесты, около минуты
node --test test/flow.test.js     # один файл
```

Что проверяют тесты:

- `flow.test.js`, `layout-kit.test.js` — независимый валидатор потоков и маршрутизатор лент;
- `generator-quality.test.js`, `generator.test.js` — схемы по всем направлениям, планетам, этапам, целям, размерам холста и режимам снабжения: нет пересечений, все блоки существуют на планете, в схеме есть главное (турели, фабрики, буры…), а ленты, боеприпасы, ингредиенты, питание и жидкости доходят до потребителей;
- `schematic-io.test.js` — круговой экспорт/импорт `.msch` со всеми видами конфигурации блоков;
- `ui-smoke.test.js` — рендер настоящих React-компонентов (выбор варианта, панель проверки, поле, инспектор, каталог) на сгенерированных схемах; браузер не нужен;
- `mechanics.test.js`, `git-update.test.js` — рецепты и скорости, скрипт обновления.

Посмотреть схему без браузера: скрипт рисует её символами и печатает вердикт проверки. Любая пара `ключ=значение` уходит в `generateLayout`:

```bash
node scripts/render-layout.mjs direction=units goal=ground stage=late footprint=wide variant=2 supplyMode=core
```

Механику игры (классы блоков, боеприпасы турелей, топливо генераторов, планы заводов юнитов) генератор берёт из `src/mechanics-data.json`. Файл собран из исходников тега v160.2; пересоздавать его нужно только при смене версии игры:

```bash
node scripts/extract-mechanics.mjs /path/to/Mindustry-160.2
```

## Обновление и дополнительные команды

В папке проекта:

```bash
# обновить код, зависимости и production-сборку
bash scripts/install-shortcut.sh update

# удалить только ярлык из меню, не удаляя проект
bash scripts/install-shortcut.sh remove

# запустить лаунчер напрямую
bash scripts/install-shortcut.sh launcher
```

Если проект был скачан ZIP-архивом, автоматическое обновление через Git работать не будет. В этом случае скачайте новый архив и замените старую папку либо используйте ручной запуск.

### Как работает автообновление

Перед запуском лаунчер проверяет обновления сам. Обновление не может «зависнуть»: сетевые команды Git ограничены по времени (по умолчанию 45 секунд) и выполняются без запросов логина, пароля и без открытия редактора. Если GitHub недоступен, приложение просто запускается в текущей версии, а в логе появляется диагностика соединения.

Поведение можно изменить переменными окружения:

```bash
BEE_SKIP_UPDATE=1 bash scripts/launcher.sh     # запустить без проверки обновлений
BEE_GIT_TIMEOUT=180 bash scripts/launcher.sh   # ждать GitHub дольше (медленная сеть)
BEE_MERGE_TIMEOUT=60 bash scripts/launcher.sh  # лимит на применение обновления
BEE_UPDATE_BRANCH=main bash scripts/launcher.sh  # какую ветку обновлять
```

Эти же настройки понимает и `bash scripts/install-shortcut.sh update`.

## Если что-то не работает

### «`npm: command not found`» или «`node: command not found`»

Node.js не установлен или терминал ещё не увидел новую установку. Установите актуальную LTS-версию Node.js, полностью закройте терминал, откройте его снова и проверьте:

```bash
node --version
npm --version
```

Нужна Node.js версии **18 или новее**.

### «`ENOENT: package.json`» или похожая ошибка

Терминал открыт не в той папке. Перейдите в папку проекта командой `cd`, затем убедитесь, что файл на месте:

```bash
ls package.json        # Linux/macOS
 dir package.json      # Windows PowerShell
```

### Порт уже занят

Остановите старый экземпляр приложения сочетанием **Ctrl+C**. Если это не помогло, закройте вкладку/терминал с предыдущим запуском и выполните `npm run dev` ещё раз. Vite также может предложить другой свободный порт — используйте адрес, который он напечатает.

### В браузере белая страница или старый интерфейс

Обновите страницу сочетанием **Ctrl+F5**. Убедитесь, что терминал с `npm run dev` всё ещё открыт и в нём нет красных сообщений об ошибках.

### Окно замирает на «Обновление кода (git pull)»

Раньше на этом шаге `git fetch` ждал сеть без ограничения времени, поэтому при проблемах с интернетом, VPN или прокси окно могло висеть бесконечно. Теперь обновление прерывается по таймауту, печатает диагностику и запускает приложение на текущей версии — ждать не нужно.

Если предупреждение появляется каждый раз:

```bash
cd esp32-----html
BEE_SKIP_UPDATE=1 bash scripts/launcher.sh   # запустить приложение, пропустив обновление
git fetch origin main                        # проверить соединение с GitHub вручную
```

Если ручной `git fetch` тоже висит, причина в сети или в прокси: сбросьте прокси командой `git config --global --unset http.proxy`, проверьте VPN и повторите. При медленном, но рабочем соединении просто увеличьте лимит: `BEE_GIT_TIMEOUT=180 bash scripts/launcher.sh`.

### Установщик завершился с ошибкой

Посмотрите последние сообщения в файле `launcher.log` в папке проекта. Самый частый порядок исправления такой:

```bash
cd esp32-----html
npm install
npm run build
npm run dev
```

Если в тексте ошибки упоминается GitHub или сеть, проверьте подключение к интернету и повторите команду.

## Возможности

- генерация схем добычи, производства, обороны, энергетики, логистики, юнитов, логики и кампании;
- настройка планеты, этапа игры, цели, размера, плотности и вспомогательных блоков;
- режимы снабжения от ядра, локального склада, дронов и гибридный режим (для логистики снабжение не нужно, режимы там не применяются);
- независимая проверка каждой схемы: ленты, ингредиенты, боеприпасы, топливо, питание и жидкости; ошибки подсвечиваются на поле, а места внешнего подключения отмечены кружками;
- генерация до трёх разных вариантов схемы с выбором компоновки до вставки в редактор;
- редактирование сетки: размещение, перетаскивание блоков, удаление, поворот, масштабирование, панорамирование, подписи и отмена/повтор;
- производство по рецептам Mindustry: отдельные входы сырья и жидкостей, проверка скоростей лент, питания и тепла;
- связь с кампанией Серпуло: экспорт продукции через Advanced Launch Pad и импорт выбранных предметов через Landing Pad;
- импорт `.msch` и строк схем из буфера обмена;
- экспорт в бинарный формат Mindustry `.msch` по плотной рамке построек, как это делает сама игра, и копирование base64-кода; в файл попадают все конфигурации: фильтры предметов, план завода юнитов, связи мостов и силовых узлов, процессоры с MLOG и связями; неизвестные игре типы конфигурации при импорте сохраняются без изменений;
- каталог ванильного содержимого Mindustry v160.2;
- сохранение избранных схем локально в браузере;
- проверка доступности обновлений при запуске.

Все схемы создаются и обрабатываются в браузере. Серверная часть для редактора не требуется.

## Как устроен генератор

Генератор не заполняет шаблон, а собирает схему из блоков с известной механикой и сразу проверяет результат отдельным валидатором, который ничего не знает о строителях.

| Слой | Файлы | Что делает |
| --- | --- | --- |
| Данные игры | `src/mechanics-data.json`, `src/block-facts.json`, `src/catalog.json` | Классы блоков, боеприпасы, топливо, планы юнитов, рецепты, размеры, стоимость, принадлежность планете |
| Поле и маршрутизатор | `src/layout-kit.js`, `src/geometry.js` | Сетка с резервами клеток, поиск пути для лент, каналов и труб с перекрёстками, «опасные» клетки рядом с блоками, которые сбрасывают продукт в любую соседнюю ленту |
| Строители | `src/gen/*.js` | По одному на направление (`mining`, `production`, `defense`, `powerplant`, `logistics`, `units`, `logicdemo`, `campaign`) и общие части: снабжение, линии, энергия, док дронов, жидкости и тепло, хранилище |
| Валидатор | `src/flow.js` | Ленты, сортировщики, мосты, разгрузчики, питание и жидкости так, как они работают в v160.2 |
| Диспетчер | `src/generator.js` | `generateLayout` и `generateLayoutVariants`: до трёх вариантов, отбрасывание одинаковых, оценка, пометка лучшего |

Что генератор делает умнее прежнего:

- **Разгрузчик на каждый ингредиент.** Каждый настроен на свой предмет, ленты не смешивают предметы, а пересечения идут через перекрёстки. Раньше все разгрузчики были настроены на медь.
- **Блоки выбираются по стоимости и планете.** Этап игры определяется по цене блока, а не по ручной метке; на планете используются только существующие там блоки (например, ремонтные блоки есть только на Серпуло, поэтому на Эрекире оборона без них).
- **Боеприпас общий.** Все турели линии принимают один предмет, который подаёт одна линия через маршрутизаторы.
- **Бур под руду.** Выбирается бур, который реально добывает эту руду (твёрдость, нужная энергия), а скорость считается по формуле игры.
- **Эрекир учитывает свои правила.** Ядро нельзя разгружать, поэтому добавляется контейнер-хаб; лучевые узлы ставятся по прямой линии; подача водорода, азота и циангена обозначена входами.
- **Энергия считается.** Мощность генераторов подбирается под потребление, силовые узлы получают явные связи в пределах дальности лазера, а при выключенной энергии схема оставляет отмеченный вход внешнего питания.
- **Варианты.** Где у задачи есть настоящие альтернативы, они различаются устройством: магистраль / гребёнка / двойная магистраль для добычи; кольцо или хаб и выделенные ленты для производства (на дронах — две, одна или три фабрики); вертикальная линия, две линии в глубину и горизонтальная батарея для обороны. Для логики, юнитов и логистики варианты — смещение, зеркало или мост вместо перекрёстка. Одинаковые схемы не повторяются.

Ограничения направлений: логика и кампания есть только на Серпуло, для Эрекира возвращается ядро с пояснением; цели «Сортировка ресурсов» и «Масс-драйверы» тоже только на Серпуло; турели Эрекира на жидких боеприпасах (титан, сублимат) не генерируются.

## Каталог и генерация Mindustry v160.2

- Каталог импортирован из официального исходника тега v160.2: **521 запись** —
  426 блоков, 22 предмета, 11 жидкостей и 62 юнита. Вкладки отделяют постройки
  кампании от объектов карты, редактора и песочницы; счётчики учитывают выбранную планету.
- Палитра и обычное размещение ограничены постройками кампании для выбранной
  планеты. Служебные и редакторские блоки остаются доступными для просмотра в
  каталоге, но не попадают в обычную схему автоматически.
- Каталог, палитра, инспектор и поле используют локальные превью из исходников
  игры. Для металлических напольных автотайлов показывается один представитель
  исходного набора вариантов. Это статичные изображения: анимация, оружие составных
  юнитов, командная окраска и стыковка не воспроизводятся.
- Источники и лицензия: `public/mindustry/ATTRIBUTION.md` и
  `public/mindustry/LICENSE-Mindustry.txt`; манифест превью —
  `src/sprite-manifest.json`.
- При генерации показываются **до трёх разных компоновок**; выбери одну, чтобы вставить
  её в редактор. Одинаковые варианты не повторяются: если для настроек есть
  только одна компоновка, интерфейс так и скажет. Для минимального производства
  варианты поворачивают выходную линию.
- Принадлежность блоков планете берётся из деревьев исследований игры: регенератор,
  ремонтирующий, сверхприводный и силовой проекторы, шоковая мина, стена из
  металлолома, грузовой конвейер и разгрузочный маршрутизатор — Серпуло;
  кинетические конвейер и маршрутизатор — Эрекир. Четыре грузовых
  конвейера/маршрутизатора занимают 3×3, а не 1×1.
- В режиме минимального производства создаётся один рецептурный модуль с
  раздельными внешними линиями сырья, жидкостей и выхода. Ленты выбираются с
  учётом скорости рецепта; требования к питанию и теплу показываются в инспекторе.
  Продукты и машины выбираются из рецептов, извлечённых в `src/block-facts.json`.
- **Экспорт кампании:** на Серпуло модуль производства может включать
  Advanced Launch Pad. Назначь сектор-получатель в игре; площадке также нужны
  масло и питание. **Импорт для обороны:** Landing Pad настраивается на выбранный
  предмет и подключается к линии снабжения. Это не автономная цепочка снабжения.
- Поле схемы поддерживает Space + перетаскивание или среднюю кнопку мыши для
  панорамирования, перетаскивание блоков, вращение, удаление, масштабирование,
  отмену и повтор. Экспорт и импорт сохраняют метаданные кампании.
- Пример: кремний Серпуло — **4×3, 5 построек**, 1,5 угля/с + 3 песка/с,
  30 энергии/с → 1,5 кремния/с без ускорения. Сырьё и энергия поступают извне,
  выход не должен забиваться; это не автономная фабрика из руды.
- Рецепты, размеры и строительные требования извлечены из `Blocks.java` v160.2.
  Смета отмечает блоки, для которых в исходнике нет данных, вместо подстановки
  выдуманной стоимости. Геометрия учитывает игровой якорь блоков и формат `.msch`.

**Границы проверки:** проверка статическая: она разбирает схему по правилам
механики v160.2, но не запускает игру и не симулирует время. Не моделируются
карта (руда, паровые жерла и нагретые поверхности под блоками предполагаются),
реальная скорость и заторы лент, полёт юнитов и исследовательское дерево сектора.
Подачу водорода, азота и циангена на Эрекире, воду и масло для площадок кампании
и внешнюю энергию схема только отмечает входами. Мощности в кампании может не
хватать — тогда проверка предупреждает. Перед использованием в секторе проверь
доступность блоков, руду под бурами и маршруты в игре.

Пересоздание ресурсов разработчиком (для обычного запуска не требуется):

```bash
python3 -m venv .venv
.venv/bin/pip install Pillow
# Распакуйте исходники Mindustry тега v160.2 вне отслеживаемых файлов репозитория.
.venv/bin/python scripts/import-mindustry-assets.py /path/to/Mindustry-160.2
npm test
npm run build
```
